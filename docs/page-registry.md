## Content sourcing (changed mid-project — read this before assuming anything is a placeholder)

The site was originally built with **entirely invented placeholder copy** (per the user's first instruction: "don't clone, use mocks for everything"). Partway through, once real DA authoring was working end-to-end, the user reversed that specifically for text: **"since we are do[ing] authoring, use data instead of mocks."** Confirmed scope via an explicit question: real text everywhere, but images stay placeholders (wknd.site's photos are licensed Adobe Stock assets per the site's own footer disclaimer — not something to reuse without a license).

So as of the current deployment:
- **All headlines, article bodies, trip descriptions, FAQ Q&A, and contributor names are the real wknd.site content**, fetched page-by-page and reproduced verbatim (see `docs/component-registry.md`'s "Real-content sourcing" note for how this was verified against Adobe's own license statement for the site).
- **The page/route set now matches the real site's actual inventory**: 5 real magazine articles (western-australia, arctic-surfing, san-diego-surf, ski-touring, guide-la-skateparks) and all 16 real adventures — not the 6 invented articles / 8 invented adventures from the first pass. The old invented-slug pages (`camper-vans-and-coastlines`, `ridge-line-climbing-weekend`, etc.) were deleted from DA and unpublished, not left alongside the real ones.
- **Images remain original placeholder SVGs**, reused across real content by theme (e.g. `article-skateparks.svg` for the real "Ultimate Guide to LA Skateparks" — same asset, just no longer paired with invented copy).
- The 7 real About Us contributors/guides (Stacey Roswells, Jake Hammer, Ian Provo, Jacob Wester, Sofia Sjöberg, Justin Barr, Kumar Selveraj) reuse the same 7 placeholder portrait images the invented contributors used — only the names/roles changed.
- The footer's real copyright text ("WKND is a fictitious adventure and travel website...") was adapted, not copied verbatim: the original says it's built with "Adobe Experience Manager Core Components" — this project isn't, so that clause was rewritten to accurately describe this build (EDS + DA) instead of leaving a false technical claim.

## Notes

- **Scope reduction**: the reference's 7-country/language selector and `/us/en/...`-style locale routing were not implemented — see `docs/component-registry.md`'s note on `.nav-region`.
- **Bugs found and fixed** (see `docs/component-registry.md`'s DA authoring constraint note for the full root-cause explanation): header/footer CSS wasn't loading at all (JS-only import bug); `hero`'s single-image variant never rendered (missing `data-active`); the mobile nav toggle's expand/collapse logic was inverted; a hero CSS rule collapsed every single-image hero to zero height once pictures had to be div-wrapped for DA; `breadcrumbs`/`meta-list`/`filters`/`byline` all lost their styling because they were authored as native lists/plain text rather than div-row blocks (rebuilt as real blocks); footer social-icon `aria-label`s were being stripped (now set client-side); a heading-level skip (h1→h3) in article bodies; `aria-label` on plain content anchors is *always* stripped by DA regardless of block context (confirmed directly) — the "Read More" CTA's SEO link-text issue was fixed by making the visible text descriptive ("Read Camping in Western Australia"), not by adding an aria-label; plus an earlier color-contrast failure, two touch-target-size failures, and a missing `<h2>` heading-order gap from the very first mock-content pass.
- **Lighthouse CLS noise**: one measurement run showed a spurious CLS regression on two pages when testing against the live CDN over a real network; re-running the exact same audit immediately after returned a perfect score. Treated as lab-data network variance, not a real defect. The same was seen with a one-off performance dip to 71 on `/` in one run; a re-run returned to 93.
- **Visual redesign pass** (this project initially shipped with invented placeholder colors/type/layout, later corrected against the reference's real computed styles — see `docs/component-registry.md`'s "Real design tokens" section): fixed heading sizes that incorrectly scaled up at wider breakpoints (reference is fixed-size at every width), card title/description sizes and the "Featured Article" eyebrow style, dropped an unconfirmed `cards.list` single-column variant once measurement showed both listing pages actually use the same 4-column grid, added the hero's real overlap-card treatment at ≥768px, and fixed a hero carousel dot touch-target-size a11y failure.
- **Heading-underline + adventures-content pass** (see `docs/component-registry.md`'s "Heading yellow rule is per-heading authored" and "Adventures listing content" notes): the yellow heading rule had been applied by a blanket first-heading CSS selector, wrongly underlining page-title H1s the reference leaves plain ("Adventures", "About Us", "Magazine", article titles); fixed with a `plain-title` opt-out section style authored onto those title sections (H1 rule kept on FAQs + the 16 adventure-detail pages, which the reference *does* underline). Separately, the adventures listing was missing its "Experience the world with us" H2 + intro paragraph (added here as an un-ruled section, then *later moved into the hero as its overlap caption* — see the "Adventures hero caption + footer side-gutter pass" note below) and titled its grid "All adventures" instead of the reference's "Current Adventures" (renamed). Root cause of the misses: the heading decoration was never measured per-heading (only "does the site have this underline"), and the ordered-text-outline diff wasn't run on the adventures listing — the skill's `visual-validation.md` now requires both.
- **Footer-spacing + page-bottom divider pass** (see `docs/component-registry.md`'s "Space above the footer" and "Page-bottom divider" notes): the dark footer was shipping flush against page content on every page — the reference has a fixed 48px gap above the footer everywhere, now added as `footer { margin-top: 3rem }`. Separately, the reference draws a thin content-width `#ebebeb` rule between the last content and the footer on the adventures listing and the five magazine articles (not on home/faqs/about-us/detail); reproduced as a `separator` section style authored onto exactly those pages. Both misses came from measuring each block's own box but never the seam between the last block and the global footer — the skill's `visual-validation.md`/`discovery-process.md` now require measuring region seams (content→footer gap + any page-bottom divider) as their own audit target.
- **FAQ + About Us correction pass** (see `docs/component-registry.md`'s "FAQ + About Us mismatches found in a later dedicated pass" note for the full list and the skill rules it drove): FAQ questions rebuilt as a collapsed `accordion`, "Need more help?" moved into a right rail at ≥1200px, the full-bleed hero banner replaced with a plain inline ~3:2 image, and the missing FAQ intro paragraph restored; About Us `team` cards re-measured and corrected (164px portraits, uppercase role line, three dark social icon buttons, shared 4-column grid with the invented `guides` variant removed), the "Our Contributors" heading and both section intro paragraphs fixed. The earlier FAQ heading-order handling (h1→h3 skip "fixed" by relocating "Need more help?" to the top of the page) is **no longer a deviation**: the accordion questions are `<h2>`, so the outline is gap-free in document order and no content is relocated.
- **Adventures hero caption + footer side-gutter pass** (see `docs/component-registry.md`'s updated "Adventures listing content" and new "Footer side gutter" notes): the adventures "Experience the world with us" heading+paragraph — previously shipped as a standalone `plain-title` section below an image-only hero — was moved *into* the hero as its overlap caption (a second content cell in the hero's slide row), so it now renders as the ~1192px white card overlapping the hero bottom, matching the reference (that `plain-title` section is removed). Separately, the footer content had a fixed 16px side gutter that hugged the screen edges at ≤1024px; widened to 24px base / 32px at ≥960px to match the reference's ~28–32px gutter. Root cause of both misses: (1) a caption card that overlaps a hero was treated as a following section rather than as the hero's own teaser — the layout skeleton never checked for the vertical *overlap* that marks the two as one composed unit; (2) the footer's horizontal content inset (left/right gutter) was only ever verified at ≥1200px, where a fixed gutter happens to match. The skill's `discovery-process.md` and `visual-validation.md` now require recording each region's horizontal gutter at every breakpoint and recognizing a hero-overlapping caption as part of the hero block.
