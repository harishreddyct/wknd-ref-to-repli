## Notes

- **Article/adventure names, contributor names, trip prices/details, and FAQ copy are all original** — invented for this project rather than copied from the reference, per the user's explicit "use mocks for everything" instruction. The "Reference URL" column above records which *reference page's structure* a mock page's template is based on, not a content source.
- **Images**: all 42 images in `/images/` are generated placeholder SVGs (abstract gradient/line illustrations), not fetched from the reference.
- **Scope reduction**: the reference's 7-country/language selector and `/us/en/...`-style locale routing were not implemented — see `docs/component-registry.md`'s note on `.nav-region`.
- **Bugs found and fixed during validation** (all in shared components, so fixing them once fixed every page that uses them): `header`/`footer` CSS wasn't being loaded at all (scripts.js only imported their JS, not their CSS — every page's nav rendered unstyled/stacked before this fix); the `hero` block's single-image ("static") variant never got the `data-active` attribute the CSS requires to be visible, so every non-carousel hero rendered as blank space; the mobile nav toggle's expand/collapse logic was inverted; hero-bleed and heading-spacing CSS gaps; a color-contrast failure on the "Members only" badge; two touch-target-size failures on the hero carousel dots; a missing `<h2>` on `/adventures` causing a heading-order skip; and a generic "Read more" link on `/magazine` failing the SEO link-text audit. All fixed at the root (component/script level), not patched per page.
- **Local dev-server limitation, not a code defect**: the static dev server used for local testing (`@web/dev-server`) needed a small custom middleware (`web-dev-server.config.mjs`) to resolve extensionless routes (e.g. `/adventures/foo`) to their `.html` file — real EDS publishing provides this pretty-URL resolution natively in production.
